# 星露谷伙伴

延续当前 Codex 对话里的玩家目标，用已接入的 stardew-companion 工具和游戏中的伙伴合作。游戏状态以工具返回为准；不要假定外部 Codex 对话与游戏内聊天共享会话。

## 一起生活与推进项目

- 玩家交代目标后，自主决定阶段、顺序和具体做法，在已同意的范围内持续推进，无需每完成一个短作业就再问一次。玩家只要求观察或商量时，先保持只读。
- 金币、工具、材料、日期和地形从游戏读取。人格、偏好与回忆帮助选择活动和交流方式；当前明确要求与真实游戏状态优先。普通缺水、障碍和材料不足先用已有能力处理；结果未知先核对，原样失败不要反复重试。
- 自由活动可以服务共同目标，也可以体现伙伴的兴趣。没有合适行动时允许待命，不必为保持忙碌制造工作。重大方向变化或超出已同意范围的资源使用再商量。
- 经营取舍使用核心指令与按需领域指导。通过 knowledge 的 `read_guidance(topic)` 读取 `crop-selection`（作物收益与规模）、`farm-region`（集中田区）、`livestock-processing`（照料加工）、`procurement-travel`（采购行程）、`wiki-lookup`（知识查询）或 `daily-rhythm`（天气节日日程）。当前执行方法就是 `execution` 主题；已读内容直接复用。
- 行程用 movement 的 `query_route` 查询原生可达路线和步行成本，不读整张地图自行寻路。到店复核与同一种交易可放在一项作业中；区分能力的 `directCall` 和 `planStep` 参数。游戏时钟在模型商量时持续前进，已有事实足够就提交，避免重复读取。
- 长项目在 `project` 保存当前 `phase`、`nextAction`、`blocker`、`prerequisites`、`window`、`progress` 和简短 `reason`；部分更新保留田区等未提及字段。接续时结合实际结果更新并结束失效待办。只记录变化与必要证据，不在每轮复制完整历史、地图和 Wiki 正文。普通完成留在任务记录；重要变化和需要玩家决定的事才主动说明。

## 农场改造

装修指整座农场的布局与施工：道路、建筑、生产区、果园、绿化与休闲空间。先读取现状，结合玩家的风格描述或参考图设计；玩家已授权自主设计时自行作出审美选择。社区作品可作为灵感，具体借鉴说明来源。知识缺口按需查询，不把网上布局当成当前农场事实。

通过 `discover_capabilities("farm_space")` 确认可执行的操作。`observe_farm_space` 提供真实坐标、占用和入口；`observe_map_image` 直接返回地图图片，当前要求玩家在该地图，不必为了截图移动玩家。按区域施工，关注建筑入口、通行、材料和现有生产。用 `manage_goal` 的 `project` 保存阶段、设计说明、布局和待解决事项（通过 memory 能力组发现参数），根据实际结果继续或调整。布局预览不等于施工完成；批量部分成功只补剩余部分，尊重玩家指定保留的区域。工具尚不支持的操作如实说明。

## 持续生产

- 玩家明确交付持续经营后，保存 active 目标，再用 `set_autonomy(goal_id=...)` 交给游戏内自主接续；该操作释放外部派工连接，不改变空闲主动帮忙开关。之后用持久化任务概览看进度，需要改回外部直接派工时先停止自主模式。已有暂停状态仍需明确继续。
- 种植先用 `query_planting_options` 比较成片候选地（容量、入口通路、清障工具、实际补水和入箱路程），在 `project.farmRegion` 保存 `locationId`、`bounds`、`reservedPaths`、`expansionDirection`。后续查询传 `region=project.farmRegion.bounds` 和对应 `location_id`，先填空再连续扩张；换区记录实际原因。枯死作物先用真实镰刀清理，不再浇水。
- 同一批已观察可种地块可依次提交所需的 `cut_grass`、`hoe_tiles`、`plant_seeds` 和覆盖该批的 `water_zone`，合计不超过64个目标；部分完成即停下重算。按实际容量选择连续一批，避免常规地块一两格一轮。
- 同一地图同批机器可按 `collect_machine` → `deposit_to_chest`（明确产物、单个指定箱子）→ `insert_machine`（只续投本批机器）组成一个生产周期，合计最多64目标。基于已观察产物和持有原料；部分完成即停。
- 大面积种植沿用短作业分批推进，按真实已完成地块继续。补水、食物和材料从实际库存与环境选择，补给后接续原目标；跨天重新看作物状态。
- 鸡舍里的鸡蛋是地面物品，通过 `observe_production` 查看实际位置，再使用 `pickup_items`。抚摸、喂食、机器加工和存箱按实际需要衔接；动物外出时，当前室内数量不代表住房剩余容量。
- 机器加工或资源恢复需要等待时，可以保存 `machineReady`、`gameTime` 或 `resource` 待办，由真实条件变化唤醒。参数通过 memory 能力组发现，避免反复查询尚未变化的状态。
- 养殖、农田照料等持续目标保持 active，今天的工作做完保存后续条件；已经达标的数量目标结束该项，继续尚未完成的经营阶段。`manage_goal(action="complete")` 会结束整个项目及其待办，用于整个项目确实结束时。建筑施工与升级需要正常游戏时间，建造和购动物依据实际服务目录、住房容量与预算决定。
- 累计播种后浇水用 `plantingEvidence.confirmedWateredCount`（全部保留账本累计值），不要再加历史累计；`batches` 提供待补浇的具体地块，`recentBatches` 只是有界预览。雨天已湿、跳过或效果为零不新增手动浇水计数。田区清理观察里的 `clearingAction` 区分草与枯苗，`hoeAfterClearingTiles` 是清后还需开垦的草格。

单个原生批次可能跳过不可执行目标并继续其余目标；步骤结束返回部分完成终态时，停止该作业的后续步骤，由下一轮依据实际成功量重算剩余工作。上述“部分完成即停”指步骤终态，不是遇到第一个跳过目标就立即中断批次。

## 游戏内决策

游戏内模型使用[游戏内执行方法](references/ingame-execution.md)，由 `read_guidance("execution")` 返回。本轮已提供令牌和实际结果；选中短作业后结束回复，原生执行器在终态后唤醒下一轮。

## 外部 Codex 连接与执行

- 已有注入的实时上下文时直接据此决定，不再读取完整状态和工作历史。外部首次接手且无实时上下文时，用简要 `get_status` 和 `get_work_overview` 确认存档、已有工作及结果。只观察时不提交任务。缺少工具时提示玩家在目标 Codex 项目运行发行包中的注册脚本，并重新打开会话；不要改写全局配置。
- 按任务需要使用观察工具；其他能力用 `discover_capabilities` 查参数，再用 `call_capability` 调用。不要猜物品、位置或能力是否存在。
- 玩家要求执行时，先用 `begin_game_turn` 开启本次决策，再使用 `submit_plan` 选择一个语义短作业，同一业务可含导航和连续原生操作；同批农场地块可用 `plant_seeds` 后接覆盖这些地块的 `water_zone`，一个作业最多32步，原生目标合计不超过64。其他业务在上一步终态后重新决定并开启新轮次。忙碌或暂停时先向玩家说明现状，不自动取消已有工作。`remember_intent` 记录目标，不代表执行授权。以工具当前 schema 为准。
- `job-selected` / `not_executed_yet` 只说明已选中；提交后用 `work_plan_overview` 查看持久化任务终态，避免 `get_status` 或 `get_work_overview` 再占用游戏唯一命令连接。避免密集轮询或重复提交。任务失败时根据错误调整；连接或权限缺失时停止重复尝试，说明阻塞原因。
- `blockedBranches` 记录同一对象、操作与原因的失败，首次失败后两次尝试仍失败就停该分支。可做清障、进食、补水或其他主任务；修复后 `query_route` 的可达证据、`observe_machines` 的实际就绪及真实补给结果可解除对应阻塞，不能只换任务名称重试。其他原因需先取得相应恢复证据再安排，不把未知结果计为失败。
- 外部 Codex 操作期间不要同时从 F8、NPC 聊天或自由模式派工。沿用已经运行的伙伴服务执行任务，不另起聊天桥接服务。游戏需已通过 SMAPI 载入存档，伙伴聊天与计划面板不暂停已接受的农活动作；其他原生菜单与游戏暂停仍按游戏规则处理。
- 用玩家的语言简短说明结果和未完成事项。保留玩家选择的称呼和相处方式，不把开发助手的身份或编码流程带入伙伴对话。

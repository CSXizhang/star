# 养殖与加工

## 尽早启动有等待期的环节

将生产链分为住房、购鸡与成长、每日照料、拾蛋、加工、成品入箱。优先解除会推迟整条链的依赖：住房可开工就尽早开工，容量就绪后在可成交窗口购鸡，有蛋与空机器后尽早投料。

购鸡数量按目标与已有数量的差额计算。饲料根据动物数量、现有供料方式、库存与下次补给机会安排。施工、成长与加工期间的其他派工按[核心接续规则](../agent-core-instructions-draft.md#接续等待与完成)安排。

## 每日照料形成一趟连贯工作

查看当天仍需照料的动物、食槽供料与可拾取产物。带足补给和背包空间，尽量一趟完成喂料缺口、抚摸与拾蛋，返回时把原料带到机器附近。

动物分布在室内外时，以住房名册确认总数，按当前位置寻找当天未照料的动物。晨起饱食字段与昨日是否吃到饲料是两个问题；判断缺料时结合食槽、库存消耗和日结算记录。当天已完成照料保留记录。

## 按机器吞吐量安排收取与续投

空机器先投料，让计时开始。原料积压时估算机器数量与加工周期，再决定是否增加机器、分批处理或保留原料。

`窗口内可完成轮数 = floor(可用加工时长 / 单批加工周期)`，`可完成原料量 = 可用机器数 × 每批原料量 × 可完成轮数`，并扣除机器已有批次占用。按库存与此容量安排交付，其余保留后续计划；窗口末续投另记下一次成熟条件。

机器成熟后，在合适的工作边界集中处理：收取、成品放进指定箱子、给空出的机器续投。机器与箱子分属不同地点时，先收完这一处，再统一运输。机器中已有原料时等待该批成熟。

赚钱目标下，有限机器优先处理单位机器时间增值较高的原料：`加工增值 = 成品价值 - 原料直接出售价值 - 额外投入`。不同品质原料可能得到相同成品时，先算增值，再决定投料顺序。玩家指定加工或留存的用途进入排期。

## 保存生产状态

每台机器保留地点、当前批次、预计成熟时机、成品去向与下一批原料。每日照料保留日期和未完成动物；补料计划保留库存与下次采购机会。

已投料表示加工开始，成品进入指定箱子才完成一次生产交付。长期目标保留下一轮照料与收取安排。

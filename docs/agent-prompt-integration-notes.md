模型常驻读取核心与短索引，需要哪个主题再读取对应参考。本说明与修改简报供开发审核。

当前接入由 `agent_instructions.py` 读取上述同一份正文。Codex 游戏进程通过 `model_instructions_file` 加载核心与短索引，用户消息里的相同正文删除；其他后端沿用统一提示入口。核心和领域文件的版本参与工作及生活会话指纹，升级只更换模型会话，保留农场、伙伴、账本与等待记录。

实机发现外部 Codex 的开启决策、查询终态流程被游戏内模型照搬。`execution` 现读取[游戏内执行方法](../agent-skills/stardew-companion/references/ingame-execution.md)，明确本轮已有令牌，派工成功后结束回复，终态由执行器带入下一轮。外部使用原 skill 的连接流程。派工回包同时给出 `handoff=end_decision`，能力发现提供动作的合法选项；缺少有效目的地的导航在保存任务前拒绝。

一趟照料允许补料、抚摸与拾取产物组合，沿用最多32步、64目标；原生批次内可跳过目标后继续，步骤返回部分完成终态时停止后续步骤并重算。原来的按操作名限制会把一次照料拆成多次模型往返，与领域指导冲突；本次按业务目的修正该限制。

游戏进程按次关闭继承的其他 MCP、插件、Apps 和 shell 等入口，不修改开发用全局配置。当前 CLI 对 `unified_exec=false` 不完全采纳，也没有可用的 `apply_patch` 禁用开关；因此仍需从实机 trace 核对实际工具使用，不能称为完全只剩 MCP 的强制隔离。

实机 r18 查明 `code_mode_host` 是当前 CLI 调用 MCP 的必要宿主，关闭它会使可见入口无法执行。该轮仅有3次模型请求、28618 token，原生执行新增0；已保留失败 trace 并停止该包。v2 专用配置恢复宿主，其他工具限制保留，以新冻结包 r20 从原夏22匹配保存继续 r19。

Wiki 增加指定页面和章节读取，同一正文缓存可用于多次查询；后段表格可以直接读取。业务阻塞按目标、操作、对象和原因保存三次失败预算，停止该分支；提供者与连接故障仍保留原来的整体保护。明确失败与未知结果分别保存，路线、机器就绪和真实补给的恢复证据可解除对应阻塞。未接入的其他恢复类型仍需针对原因补充，不能自动当作恢复。

原生观察也有两项根因修正：机器 `lastInputItem` 是上一次配方历史，收空后仍存在，不能据此把空机器标成占用；当前产物、加工计时与就绪标志决定 `hasInput`。鸡舍补料按住房名册、容量及已有食槽计算缺口，室外放养不改变住户数；建筑别名只在唯一匹配时接受，并以解析后的真实室内身份校验伙伴位置。

新提示实机 r19 从原夏22保存正常推进并保存到夏24，世界与伙伴资源日51匹配。累计种后手浇200保持，10鸡保持，夏23实际抚摸10只；新增拾蛋44枚、三次收取入箱续投，原箱蛋黄酱17→20。r20确认鸡全部在室外时实际补入8份，将食槽2→10；修正机器观察后，模型识别原右机为空并真实投料，两机在夏25保存中均成熟。r20夏24实际抚摸7只，未完成3只如实保留。

r21使用游戏内执行说明接续，没有另发玩家目标。夏25实际抚摸10只、拾蛋20枚，两机完成两轮收取→原箱入库→续投，共收取4份、入箱4份、续投4枚普通蛋。第一批照料完成7只后因第8只移动而停止，下一轮仅完成剩余3只。正常原生过夜保存到夏26，伙伴资源日53，箱内实物25份蛋黄酱，两机再次成熟。数量种植目标保持200、待补浇0；持续经营目标及下一日照料、机器成熟条件保留。暂停截图的当前、上一实际结果和下一步同步，所属进程已停止，日常安装、保存和源保存前后摘要一致。

最终匹配来源为 `.test-runs/production-decision-20261001-r21`，[结构化实机证据](../.test-runs/production-decision-20261001-r21/evidence/prompt-integration-acceptance.json)包含原生效果、箱内物品、保存哈希、用量和边界；[暂停面板截图](../.test-runs/production-decision-20261001-r21/evidence/f8-ui-r21-saved-summer26-paused.png)为真实游戏截图。当前源码与同一份伙伴状态已冻结为 `package-r23`，1741份文件完整性核验通过。r21实际运行的是 `package-r22`；r23只再明确入口发现与调用分开、临时缓存不跨决策，并更新补料工具说明，未重跑整段经营。

## 接入顺序

1. 核心正文集中维护，各执行入口每次请求注入一次。检查游戏聊天、自主工作与游戏 MCP 的实际提示，清理重复拼接及“优先不花钱”等冲突偏好。
2. 执行 skill 保留动作流程、工具前置条件与主题索引。`read_guidance(topic)` 只读取固定的六份参考或游戏内执行说明，随发行包打包；具体参数与结果含义由工具说明维护。
3. 游戏伙伴使用专用配置，工具范围集中在游戏观察、执行、知识查询与指导读取。检查继承配置带入的多余工具，开发环境继续服务项目开发。
4. 项目状态保存成果、主田区、指定箱子、阻塞与等待条件。机器成熟、营业恢复和跨日事件触发后继续派工，面板三栏从同一份状态生成。
5. 重试记录按同一原因的阻塞归并。首次失败后计有针对性的修正尝试；修正后连续失败两次停止该分支，保留恢复条件，其他分支继续。结果未知时先对账，取得明确失败结果后再计失败尝试。

当前这轮已记录的隔离验收基线为 `gpt-6.1-sol / high`，见[验收记录](../.local/production-acceptance-sol61.md)。仓库默认配置也支持 Kimi，后续接入按实际所选后端核对。提示压缩幅度依据本项目需求决定。

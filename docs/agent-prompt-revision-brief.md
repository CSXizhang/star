# 星露谷伙伴提示词修改简报

状态：供修改 `agent-core-instructions-draft.md` 与 `agent-domain-guidance-draft.md` 使用。日期：2026年10月1日。

本简报汇总对两份草案的审核结论与外部调研结果，供执行修改的模型使用。两份草案位于本目录：

- `agent-core-instructions-draft.md`（常驻核心指令，约 9.6KB）
- `agent-domain-guidance-draft.md`（按需加载的领域参考，约 13.7KB）

## 一、调研结论

### 1.1 2026 年 Anthropic 指南（主要依据）

来源：Anthropic 2026-07-24 "The new rules of context engineering for Claude 5 generation models"（claude.com/blog），经 [developersdigest 解读](https://www.developersdigest.tech/blog/context-engineering-claude-5-new-rules-2026)核对；另参考 [2026-09 Anthropic 提示词指南改写总结](https://www.mindstudio.ai/blog/claude-prompting-best-practices-2026)。

关键事实与规则：

1. Anthropic 为 Claude 5 代模型删除 Claude Code 系统提示 80% 以上内容，编码评测无可测量下降。六个转变：
   - **规则 → 判断**：用判断原则替代 "always/never" 硬规则（例：以"写得像周围代码"取代"默认不写注释"）。
   - **例子 → 接口设计**：官方实验发现例子会把模型限制在更窄的探索空间。工具应靠参数名、枚举值、返回结构自解释；"需要例子才能用的工具是接口设计错了"。
   - **全部前置 → 渐进披露**：按需加载，CLAUDE.md 超 50 行应拆分。
   - **重复 → 单一出处**：系统提示与工具描述不重复同一指令。
   - **手工记忆 → 自动记忆**。
   - **简单规格 → 丰富引用**（测试、rubric 等可执行引用）。
2. 正向指令优于禁令；给规则附理由比裸命令泛化更好。
3. 显式"完成后自查输出质量"类验证指令被列为应删除的习惯（Claude 5 已内置自检，再写会拖慢并可能自相矛盾）。
4. 删规则的裁决方式："删一条，跑评测，分数不掉就是过度约束。"

### 1.2 2025 年 Anthropic 指南（仍部分有效）

来源：[Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)（2025-09-29）。

- 上下文是有限资源，目标是"最小的高信号 token 集合"；系统提示处于"right altitude"（既不硬编码脆弱逻辑，也不空泛）。
- 该文建议保留 few-shot 例子——**此条已被 2026 年指南取代**，以 2026 年为准。
- 跨代不变的元规则：**先用最小提示跑真实评测，按失败模式增删内容**。

### 1.3 模型依赖性限定

2026 年结论按 Claude 5 代校准。本项目伙伴实际运行在 Kimi 模型上，能力档位不同，不能照搬"删 80% 无损失"的数字。因此所有删减必须通过本简报第五节的评测集裁决，不做先验删除。

## 二、对两份草案的总体判断

骨架正确（常驻核心 + 按需领域参考的分层符合渐进披露），方法论写法（选事四问题、接续三要素）符合 2026 年方向。需要修改的是：数值例子偏重、部分规则可改为判断式、开发内容与模型指令物理混排、以及若干覆盖缺口。

## 三、对 `agent-core-instructions-draft.md` 的修改指令

1. **保持纯方法论，不加入数值例子**（当前已符合，勿引入）。
2. **合并重复的接续/等待规则**：当前在"把目标变成可接续的项目""选择下一项工作的标准""接续、等待与完成"三处重复。保留"接续、等待与完成"一节为权威表述（含等待三要素：在等什么、触发条件、触发后做什么），其余两处各压缩为一行引用。
3. **删除动机性/同义反复句**：如"让新结果真正改变下一次选择""数量由模型计算"。目标压缩约 10% 篇幅。
4. **新增"边界"一节，用判断式而非禁令清单**：核心意思是——玩家的留存安排、任务物品、预留资金和已有布局属于不可逆损失，处置前先确认；普通经营选择自主决定。硬规则只保留真正不可逆操作这一层。
5. **新增职责范围一句话**：明确伙伴负责农场经营、养殖与加工；下矿、战斗、社交等除非玩家明确要求，不主动进行（按项目实际范围调整措辞）。
6. **新增失败重试上限**：同一问题改变前提后仍失败两次，停止重试并向玩家说明具体缺口。与现有"下一次尝试应有一个具体改变"衔接。
7. **保留"完成前逐项核对完成条件"**：这是跨日状态对账（读项目记录比对完成量），属于工作流而非输出自查，不受 2026 年"删除验证指令"转变影响。措辞上强调是读取记录核对，而非"再检查一遍"。
8. **新增自由对话汇报风格一句**：常规动作只同步面板，主动向玩家说话限于阶段成果、实质取舍与阻塞，每次不超过三句。
9. **物理拆分**：将"开发接入说明""借鉴来源与具体改写"两节移出到独立的 `agent-prompt-integration-notes.md`，模型指令文件只含模型指令正文。

## 四、对 `agent-domain-guidance-draft.md` 的修改指令

1. **压缩蓝莓/甜瓜/萝卜对照表**（当前第 42-56 行）：删除整张三作物对照表与 400g 资金变体，保留收益计算公式（`收获轮数`、`净收益`）和一句方法要求："先写出当前日期下的收获日历，再按同一截止日比较净收益。"夏 22 日结论翻转的要点用一句话保留（"截止日变化会翻转结论，须按当前日期重算"），不保留完整演算。
2. **保留 Wiki 字段清单**（季节、首收天数、再生间隔、产量、价格）——这是领域知识不是例子。
3. **知识查询返回格式**：将示例代码块改为字段清单（逐项列出必含字段），不用示例输出。
4. **面板三栏的示例列**：保留（属输出契约，删除风险由评测裁决），但示例值改为占位描述（如"对象+数量+进行中操作"），去除具体农场数值。
5. **新增"日内节奏"主题**（当前五个主题之外的第六个）：晨起检查天气与节日（雨天免浇水、节日关店）、当天营业窗口、傍晚前安排返回与睡觉、避免 2:00 昏倒惩罚。以原则式书写，不堆数值。
6. **天气与节日并入采购与行程**：雨天释放的照料时间可用于其他分支；节日既是关店风险也是特殊采购机会。
7. **删除结尾"下一轮沿用现有隔离保存……"验收观察段落**：属项目管理内容，移入 `agent-prompt-integration-notes.md`。
8. **"开发接入与验收"一节**同样移出。
9. **按主题拆为五个（修改后六个）独立文件**：种植选择、田区规划、养殖与加工、采购与行程、知识查询、日内节奏。主题索引表保留在某个入口文件中。

## 五、评测集（删减的裁决工具）

修改前先建立最小评测集，每处删减跑一遍，行为不退化才接受删除。场景及机械可判的预期行为：

| 场景 | 预期行为（判定点） |
| --- | --- |
| 夏 1 日，赚钱目标，选种 | 先写出收获日历再算净收益；结论为蓝莓并给出理由 |
| 夏 22 日，赚钱目标，选种 | 按剩余天数重算；结论翻转为萝卜 |
| 20 颗目标，已种并浇水 12 颗、8 颗只播种 | 下一步只浇 8 颗，再安排新种植；不重复已完成的 12 颗 |
| 机器成熟通知到达 | 收取、成品入指定箱、续投，并记录下一次成熟条件 |
| 16:40，商店 17:00 关店，行程需 25 分钟 | 判断来不及，改做其他工作并记录下一次营业机会 |
| 同一移动目标连续失败两次 | 停止重试，向玩家说明具体缺口 |

执行方式：同一批场景分别在"原版提示词"和"每轮删减版"下运行，对比判定点通过率。任何删减导致判定点退化即回滚该处删减。

## 六、执行修改时的约束（给修改者的元指令）

- 只做本简报列出的增删，不额外发挥；不确定是否该删的内容，默认保留并标注"待评测裁决"。
- 修改后全文通读一遍，消除因删减产生的指代断裂（如"上述例子"指向已删内容）。
- 保持现有语言（中文）与Markdown结构层级；不引入 emoji。
- 数值公式、Wiki 字段名、游戏机制事实不得改动。
- 输出：修改后的各文件全文 + 一份变更清单（每条对应本简报第几条指令）。

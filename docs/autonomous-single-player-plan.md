# 真实模型单人游玩方案

状态：仅方案，本轮不实现自主玩家模式。先完成 F8 管理窗口与 NPC 对话的分离。

## 目标

让现有伙伴模型成为单人游戏的唯一玩家，自主决定经营目标、工作安排和作息。不给逐日路线，不安排另一个模型扮演主人，不让游玩模型同时担任评委。运行结束后，由人或独立评估模型查看最终存档与过程。

这是一段真实模型驱动的开放游玩，不是模拟回复、固定动作脚本或回归用例。初始提示只交代“正常经营农场，目标和作息自行决定”及能力边界，现实运行时长和费用由外层控制。

## 改动评估

属于中到大改动，不能靠打开主动模式或替换一句提示词完成。

| 现有实现 | 自主玩家模式需要的改造 |
| --- | --- |
| ModEntry 创建独立 Farmer，FarmerMechanicsActor 管理伙伴自己的位置、工具、体力和背包 | 单独的玩家角色适配器绑定实际 Game1.player；保留正常玩家库存、资金、技能和原生工具生命周期，不再创建第二个伙伴角色 |
| CompanionRestController 只让伙伴上床，明确不结束玩家一天 | 玩家通过原生睡觉交互结束一天，处理结算、升级选择、保存和次日起床；不能直接修改日期或强制补满资源 |
| 工作循环承接玩家指令、范围和待确认事项 | 独立的自主决策入口：观察、选目标、执行、根据结果改计划；不等待不存在的主人确认，也不把“请求确认”当成正常前置 |
| 原生动作覆盖农活、采购、生产、建筑服务等部分能力 | 逐项审计真实主角色调用、跨场景更新、门与商店、背包满、剧情和选择菜单；不能假设伙伴动作换个 actor 就都可用 |
| 已有隔离存档启动和执行记录 | 增加长时间运行监督、连续跨日和断点继续、图像记录，以及结束后的独立交付 |

已有 IFarmerActor、导航、动作状态机、MCP 工具、MiniMax 适配和隔离启动流程可以复用，因此不需要从零重做；主要风险集中在主角色语义、原生菜单与跨日生命周期。只把独立伙伴留在农场自动干活不能满足本目标。

## 实现边界

新增明确的单人自主运行模式，与日常伙伴模式隔离。只启动复制的游戏存档，运行目录、会话、工作状态和证据目录独立；不改用户日常存档，不沿用伙伴自己的钱包和检查点覆盖真实玩家。

模型通过结构化观察和游戏操作工具游玩，不要求每走一步都调用视觉模型。工具可执行到某个位置、对选定目标使用工具、与对象交互、选择当前菜单选项等有界动作；目标、购买什么、何时返程睡觉由模型决定。观察只提供当前角色正常可获知的事实，未知能力返回明确结果，不伪造成功。

游戏运行中不能反复临时替换全局 Game1.player 来冒充角色控制。适配器需要明确谁拥有输入、谁更新位置和工具状态、镜头跟随谁，以及模型思考时游戏时间如何推进。首版保留正常游戏时间；将模型延迟、菜单暂停和卡顿单独记录，避免把延迟造成的失败全归因于规划。

提供方使用真实模型和真实工具。每个运行保持自己的会话，跨日更新事实，重启遵守已实现的上下文去重，不反复灌入完整历史。公开操作计划可记录，但不要求或依赖模型输出隐藏推理。

## 分阶段落地

1. **玩家控制与跨日闭环**：绑定真实玩家，验证原生移动、使用工具、背包、场景切换、睡觉、结算与存档；在玩家模式下关闭独立伙伴生成和恢复逻辑。这个基础阶段仍需工程验证，但不把它称作自由游玩结果。
2. **真实模型开放游玩**：接入自主目标入口和可用菜单操作，只给宽泛背景，连续玩 2～3 个游戏日。遇到失败由模型自行调整；基础能力缺失明确记录，禁止偷偷由脚本代替它完成任务。
3. **运行监督与交付**：达到时长、费用或游戏日上限后停止新决策；尽可能正常保存，不能保存时保留最后有效存档并标记未保存尾段。随后运行独立分析，不再影响游玩过程。

首版不承诺全游戏覆盖。对钓鱼小游戏、复杂剧情、战斗等尚未适配的交互，需要明确列出可用范围和阻塞事件；不能通过加钱、传送、无敌或绕过原生消耗来“打通”自由游玩。

## 监督与证据

监督器只负责连接恢复、进程健康、费用和时长边界，不替模型决定下一项农活。持续无状态变化、同一失败反复出现、卡在未知菜单时，记录卡点；最多做有界技术恢复，无法恢复则结束并保留失败现场。

每次运行交付：

- 初始与最终存档、版本、模型配置和运行参数。
- 带时间索引的画面记录：关键交互截图与定时帧；如启用视频，记录缺帧和实际覆盖区间，不把截图称作录像。
- 工具请求、真实返回、公开目标更新、游戏事件和错误 trace。
- 每日资金、体力、背包、农场变化、睡觉时间、死亡或昏倒等事实摘要。
- 真实调用量、费用估算依据、停止原因与未解决问题。

最终评估看实际发展、目标持续性、资源使用和失败恢复。模型自己的总结仅作为一份自述，不作为完成事实。结果不预设“必须赚钱多少”或“必须按路线完成”，也不在游玩中用评测指令干预目标。

## 与本轮 UI 的关系

本轮只调整日常伙伴交互：NPC 负责对话，F8 负责滚动记录、工作管理和设置。自主玩家模式未来会需要独立的运行控制与回看入口，但不为尚未实现的功能在当前 UI 添加开关。

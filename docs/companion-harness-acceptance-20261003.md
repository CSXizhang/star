# 0.3.11：行动自由度、范围保留与真实反馈

继续 PR #9。此次修改针对“模型被不准确的规则限制、真实结果没有完整回传、具体目标被摘要丢失、会话和用量口径不一致”。保留 0.3.10 的原生 F8、Esc、床恢复、动作动画和退出进程清理。

## 修改与原因

| 问题 | 修正 | 主要文件 |
| --- | --- | --- |
| 整个作业被固定 64 格、业务类别和同地图组合限制 | 取消这些限制，允许一个可中断作业组合合法原子步骤及跨地图导航；仍检查真实资源、原生地图条件、暂停、单演员和命令终态 | `work_state.py`、`scheduler.py`、`mcp_server.py`、`agent_instructions.py`、伙伴执行说明 |
| 多步骤完成回报只保留末步，超时恢复可能读旧 task | 保存逐步反馈，恢复后重新读取任务；下一轮、玩家回报和记忆共用真实成功、跳过、失败、未处理及原因，未知效果不推成零或重放 | `job_feedback.py`、`plan_executor.py`、`chat_bridge.py` |
| 完整观察到所选范围无工作却报告“未确认变化”，并自行触发续轮 | 保留操作范围的 `goalSatisfied`，严格核实后标记 `knownNoWork`；空操作不触发新决策，资源、世界和目标变更仍能唤醒；提示明确闲时帮忙开关 | `job_feedback.py`、`chat_bridge.py` |
| 自动操作丢原生版本及错误类别，补水候选点被当成农活剩余量 | 传递终态版本、命令 ID、资源增减与原生原因；成功补水是一次服务，候选水源点单独计数 | `scheduler.py`、`plan_executor.py`、`job_feedback.py` |
| 已采纳安排再次 adopt 报错或摘要变了但准备类型仍旧 | 同一 goal 使用 revise 更新范围、准备类型与约定，撤掉尚未执行的旧待办；在途和未知命令继续核对，不盲目重派 | `companion_milestones.py`、`work_state.py`、`life_chat.py`、`mcp_server.py`、`chat_bridge.py` |
| 玩家给具体候选格，下一轮只看到“指定 19 格”，auto 又扩大到全农场 | 保存地点和候选坐标；auto 与当前真实候选取交集后再分批，授权比较和派发共用完整范围投影；空范围不回退全农场，截断观察不冒充完成 | `companion_milestones.py`、`decision_context.py`、`life_chat.py`、`mcp_server.py`、`work_state.py`、`scheduler.py`、`plan_executor.py`、`chat_bridge.py` |
| 直接调用原子工具时新建空约束目标，脱离当前已接受安排 | 原子工具优先继承当轮绑定目标与约束，只有无绑定时才新建普通目标；返回选择的 goal ID | `mcp_server.py` |
| 上下文太少导致反复查询，查询又返回大量无关详情 | 默认提供有来源和未知标记的当前资源、农活、种植候选与种子来源摘要；能力分组可读取完整 schema，详情按需取得 | `decision_context.py`、`mcp_server.py` |
| Windows 命令行过长、取消前丢 CID、统计把缓存和上下文混在一起 | agy 经标准输入发送 NDJSON，及早绑定 CID，取消后清理本次进程树并保留已收到结果；按 response ID 持久化用量凭据，支持迟到补计；最新输入上下文与累计 token 分开 | `agy_process.py`、`chat_bridge.py`、`usage_meter.py`、`usage_display.py` |

没有新增授权 LLM、proposal-id gate、中文关键词授权分类器或通用状态机。chat / plan 继续属于生活会话，授权由现有模型结合玩家原话、偏好和约定判断；参数、原生条件和命令终态保护执行过程。

## agy 实机验收

使用游戏原生运行进程及其自动启动的正式 Bridge，后端 `agy`、模型 `gemini-3.8-flash-low`、effort `low`。隔离的克隆存档由测试驱动布置真实游戏作物、种子、体力和水量；操作经过正式聊天/设置控件，效果读取原生作物与命令回执。没有伪造成功结果、另起 Bridge、替模型提交计划或改游戏时钟。键盘关闭验收由游戏线程调用正式 Esc 处理路径，不表述为人工键盘操作。

`agy-harness-0311-r5` 已通过真实床恢复、同日自动续工、80 格浇水、补水后续作和 Esc。伙伴体力由 1 恢复到 270，醒来后无玩家行动指令；80 个唯一目标全部变为已浇水，两次补水成功后继续浇水。5 个已完成模型回合复用一个 CID，退出前另启动 1 回合，7 个原生执行记录。报告在本机 `.test-runs/agy-harness-0311-r5/evidence/harness-agy-rest-startup-water-escape-3f0dede8.json`。

这轮可准确计量的 19 个 generation：输入 96,566、输出 2,359、缓存输入 390,261，含缓存的使用量下界为 **489,186 token + 1 项未知响应**。三个原生用量 UI 快照与去重后的凭据一致；最后一次输入上下文 **37,465**，没有把累计使用量当作上下文。退出前新启动的尾部无额外可计量记录，不能推定零费用。正常退出后，本轮相关 Python/agy 进程为零，随包 `_asyncio.pyd` 可独占读写。

验收中发现的失败保留原始证据：r2 模型已传 `preparation=[plant,water]`，旧工具却忽略参数；r4 已正确保存准备类型，但摘要丢失候选坐标，模型种下两个指定空格后又在范围外开垦播种五格。r6 已真实返回播种 19→2、跳过 17，但 `water_auto` 又浇了范围外的一格，且验收脚本误把未选择作业的 decision token 当作正在执行。这几轮均没有计为严格通过。随后修正 auto 的实际候选交集，保留默认 `None` 省略兼容性，并加强实机检查要求浇水格集合恰好等于新种两格。r3 的床恢复和醒来成功，但续作受重叠验收启动器切换 MCP 配置影响，r5 在全新独立运行中重测通过。

## 兼容与限制

旧存档字段可缺省，无需迁移。已有持久目标通过 revise 保留同一 goal。计划保持一个当前可中断作业及最多 32 个串行步骤的结构边界；这不是格数或业务预算。真实游戏资源、路径与暂停仍可能使一段行动部分完成。

旧 `plant_crop_workflow` 工具名保留，模型持久化入口会在派发前返回 `saved=False` 和拆成取种/开垦/播种/浇水的指引，避免内部多次派发丢回执和恢复错命令 ID；这是明确的工具行为兼容变化。公开原子操作仍可组合。

未知用量仍为未知；缓存 token 有使用量，不据此虚构金额。最早一轮原始 agy 记录有一个无法准确关联的响应，保留未知而不估算。较多无工作回合仍会耗 token，不宣称模型调用成本已经归零。此前第三方 Mod 的卡顿没有在这次隔离运行中全面复测，不能据此保证所有保存、加载或第三方卡顿消失。

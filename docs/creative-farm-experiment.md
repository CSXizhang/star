# 无限材料自主农场创作实验

从未经整理的单人标准农场开始，让同一个 Agent 自行决定风格、建设内容、整体布局及树草取舍，完成制作、施工、自检和交付。测试环境只提供无限基础材料、已核实的配方、足够等级的工具、体力与固定白天；原始树草和障碍完整保留，成品由模型通过原生动作实际制作摆放。

这是 PR16 基础上的 `creative-farm` 实验预设，单独运行，不加入默认三组伙伴实机回归。当前实现与验证状态见本文末尾。

## 先约定什么样的农场

默认设计约定保存在 `tools/companion_acceptance/cases.json` 的 `creative-farm.designBrief`：

当前交付对象是整座农场的一件完整作品：从全景看出整体构思、空间联系、景观层次和值得近看的细节。模型自行选择主题、内容、风格、布局与树草取舍，把建成空间、保留的自然景观及留白纳入整体关系，不要求每个角落施工，也不规定分区、图案、数量或覆盖率。

实际任务仍由 `designBrief + instruction` 原文拼接、单次发送并核对运行层收件原文；现有 `summary`、`layout`、`remaining` 保存整体构思、当前安排和未完事项，方案可改，玩家约定的交付范围保留。收尾使用最后一次施工后实际查看的全景及必要局部，对照整场作品目标继续处理问题；不要求固定精修轮数或没有任何不足，通用核心说明不把整场目标强加给其他局部任务。

可选灵感来自 [Crowshadow](https://forums.stardewvalley.net/threads/my-perfect-and-only-farm-10-years-300-hours.4782/)、[Bloodless](https://forums.stardewvalley.net/threads/my-one-and-only-farm-finally-fully-updated.34643/) 与 [Overhill Farm](https://forums.stardewvalley.net/threads/overhill-farm.5823/)。它们启发空间组织、材料搭配与生活感，模型可以自由借鉴或另选方向；参考里的地图、建筑和植物不代表本轮可用能力，实际配方和空间观察才是依据。

本地清单 `manifest.json` 的 `images` 保存每张图的 `id`、`title`、`author`、`source`、相邻文件名 `file` 和 `sha256`；通过 `-ReferenceImagesManifest` 选择少量 PNG/JPEG。启动器只将列出的图和清单复制到隔离运行的 `config/reference-images/`，同一 `consult.read_reference_image` 操作不传参数即返回全部选定图片、顺序与来源，传 `image_id` 可单独重看；八个具名入口保持不变，不修改客户端的额外工具配置。

`query_game.observe_map_image` 不传 `region` 保持原生全图，传 `{x,y,width,height}` 返回原生局部截图，附绝对格点范围、像素关系和捕获版本。临时 ScreenshotRegion 在成功或异常后恢复，不移动角色；模型自行选择观察时机，精确施工仍使用结构化空间观察。图片类型单测不等于真实后端理解，正式运行前需用选定后端结合参考图、局部画面和真实物件做小范围核对。

本轮只发送一次完整要求，不补施工坐标、不逐步催促，也不增加交付后的改造挑战。有限工程默认创建可完成的 `stage`，已有长期 `main` 的授权和保护规则保持不变；未完成工程沿用原会话继续执行，完成后由既有本地状态触发截图、保存和退出。

可通过 `-DesignBriefPath` 使用其他 UTF-8 创作原文；环境说明与技术检查仍保留，数量仅记录施工规模，不作为默认完成门槛或审美认定。

## 这一版的创作环境

### 可选：按图建设与原生农牧服务

玩家确认具体设计图后，可同时传 `-DesignBriefPath`、`-ReferenceImagesManifest` 和 `-NativeFarmServices`，沿用同一 creative-farm 工程与八个工具入口；不传开关时保持下面的固定白天规则。开关选择 `nativeServicesInstruction` 替换默认环境说明，完整任务仍只发送一次。图片角色由玩家约定决定，既可作为自由创作灵感，也可作为确认的施工设计；真实地形、原生尺寸和服务规则优先。

本轮使用[木石田园设计要求](woodstone-farm-design.md)，建设住宅附近的四块田、鸡舍畜棚放牧院、储物加工庭院与池岸休息处，不要求改造全农场。确认的概念图只在本机清单中提供；执行时传 `-DesignBriefPath docs/woodstone-farm-design.md -NativeFarmServices`，同时指定自己的本地图片清单。

该模式不冻结时钟，允许原生睡眠跨日，保留现有思考暂停和正常营业时间。空闲边界将钱包不足一百万的部分补足并记录差额，白名单材料和体力照常补给，没有累计费用上限；建筑、动物、作物和成品不注入，由模型原生订建、等待工期、购买、种植与照料。

技术记录补充各建筑的完成状态、门口可达性、居民 ID 及现有 livestock 观察。仅在该模式允许新建鸡舍、畜棚和筒仓及采购，并对照去重后的原生订建、动物购买回执；原建筑、水体、入口、制作摆放及保存检查继续保留。调试与正式施工使用不同原始副本，各轮证据单独归档，不将图、存档或私人记录加入发行包。

玩家自玩共用原生订建、动物购买、饲喂、抚摸、动物门及加工设施操作；到真实柜台后直接调用服务工具，无须先打开建造或购买菜单。原生问题选项通过 DialogueBox 的点击流程处理，保留其对话标记清理及替换菜单生命周期，睡眠回答仍由过夜动作负责。

| 部分 | 本轮规则 |
| --- | --- |
| 存档 | 使用未经整理的春季或夏季单人标准农场隔离副本；不改季节、不清空地面，开工前另存初始存档、完整占地和全图。 |
| 材料 | 白名单基础材料在角色背包中持续补足，保留制作产物所需空槽。补给写入独立账本。 |
| 配方 | 开放本轮选定的原生配方，具体清单在启动记录中由游戏数据确认。成品需要模型实际制作。 |
| 时间与体力 | 固定白天，持续补足体力，让本轮集中验证设计与施工。 |
| 游戏动作 | 沿用正式清理、制作、放置、耕地和移动接口；玩家模式支持工具等级校验、树桩倒木及巨石的多次原生挥击，保留碰撞、伤害、掉落和回执。 |
| 持续执行 | 沿用原会话与现有项目记录，一次普通回复或一个区域完成后仍可继续。 |
| 角色 | 使用 AI 自玩模式，模型控制玩家角色独立施工，沿用正式 F9 托管与接管入口。 |
| 范围 | 开放经本机数据筛选的铺装、围栏、灯具、设施、草籽和一簇鲜花；四种花种仅作为制作原料，不提供成熟作物、不采购、不跨日养成。 |

无限补给只存在于 TestDriver 的隔离预设中。生产 Mod 的制作、物品放置和资源规则保持原生行为。材料补给在动作空闲边界发生，避免改变执行中一次制作的成本和回执。

材料盘以四种花种替换无用的树液、干草、铱锭和织布机用松焦油，保留十二个初始成品空槽，保留电池组以制作灯柱，普通与优质洒水器仍可制作。上层灯具、花饰、设施和围栏在原生允许时可以与铺装、草地或无作物耕地共存，摆放回执核对新增物件、消耗和底层保留；树木、作物、已有实体和入口仍受保护。

## 完成与评审

测试同时检查项目状态、真实游戏布局和动作记录。完整设计约定单条提交后核对运行层收到的原文，发送失败立即停止，不重发或放任无关自玩；聊天输入与协议统一支持 8192 字符。首次回复完成不会结束实验；模型在项目的 `summary` 和 `layout` 保留设计说明与布局，完成工程、原生动作结束且本轮执行稳定后，采集最终证据。

自动检查的内容包括：

- 本轮项目留下方案、布局和收尾状态，而非关闭一个无关目标。
- 确实发生自主施工，新增摆放物有对应原生制作、消耗与摆放回执；物件和铺装数量只记录。
- 初始树木、草地、小杂物与大型障碍完整记录；清理与保留由模型选择，实际变化与回执对应。
- 原有建筑、水体与入口保留；对实际建造的箱子和加工设施检查可达操作位置，没有这些设施也不强制补建。
- 动作终态、实际布局与存档状态一致，不要求指定田地、加工区或其他内容。
- 初始与最终原生全农场图、最终布局和执行记录齐全。
- 完成后保存隔离副本，再正常退出。

**整体观感、内容充实程度、使用是否舒服，以及创作说明与实景是否吻合，由人工看真实图片点评。** 技术通过不等于视觉出色，不新增审美评分、额外评审 Agent 或蓝图审批；效果普通也保留真实成果并指出具体问题。

部分施工回执优先列出未完成位置及其附近真实占地，模型自行处理障碍、更新原方案并逐区核对后收尾。全图占地被截断时继续查询施工分区，不能把缺少树草条目当作空地，也不能用最初设计代替实际布局。

本实验没有总运行时限，可以持续通宵工作，直到项目完成、玩家 F9 接管、收到明确停止请求或出现实际运行错误。停止或出错时尝试保留当前状态、项目进度、实际画面与隔离存档，并报告未完成内容。连接、单次回执和结束保存仍有故障超时；原生快照等待同一标签最多 120 秒，容纳繁忙游戏线程的较晚回执，不重发动作，也不会按整个装修项目的累计时长中断正常施工。

## 在 Windows 上运行

准备当前分支对应的干净完整包、已登录的模型客户端、Stardew Valley、SMAPI、.NET SDK，以及源码开发所需的 Python 环境，具体构建步骤见[参与开发](../CONTRIBUTING.md)。发行包应包含 PR16 的持续执行改动；TestDriver 由入口脚本现场构建。

关闭正在运行的游戏，在仓库根目录运行一次：

```powershell
.\tools\run-companion-presets.ps1 `
  -ReleaseDir "C:\star\release\StardewAI.Companion.Mod" `
  -SavePath "C:\my-test-saves\Farm_123456" `
  -Cases creative-farm `
  -AcceptanceBackend mcode
```

路径替换为本机目录；`-SavePath` 是单人标准农场的只读来源。mcode 的模型可留空，沿用客户端配置；使用 `agy` 时建议通过 `-AcceptanceModel` 明确指定本次要测试的模型，并按需填写 `-AcceptanceEffort`。

`creative-farm` 单独运行，没有总时长预算，也无需传 `-TimeoutSeconds`；该参数仅用于其他有限时长的回归场景。进度与全场观察每 15 分钟进行一次，期间只读取本地控制、工程状态及结束回执；工程完成、运行故障和 F9 接管会及时进入保存流程，F9 后不重新授权。它会关闭周期窗口截图，保留开工前与结束时的原生全图、状态和动作账本，并在有真实施工变化时最多额外保留四张低频过程全图。使用自己的设计描述时，追加：

```powershell
  -DesignBriefPath "C:\star\farm-brief.txt"
```

本轮附参考图时另传 `-ReferenceImagesManifest "C:\star\local-references\manifest.json"`。图片、来源清单和私人运行数据只保留本地，不纳入源码或发行包；复用旧成果进行图片理解调试，与新的原始农场正式运行分别留档。

报告位于 `.test-runs/<运行名>-game/evidence/creative-farm-report.md`，并归档设计约定、项目方案变化、原生布局、制作与摆放记录、材料补给和前后全农场 PNG。全图通过现有 `InspectMapImage` 调用游戏原生地图截图生成，直接对应实际施工结果；截图完成后才进入交付收尾。

主要交付包括 `creative-farm-before.png`、`creative-farm-final.png`、`creative-farm-design.md` 和 `creative-farm-design.json`。装修后的存档目录、文件大小与哈希写入报告的 `savedFarm`，可用副本查看作品；它保留本次创作实验提供的材料与配方条件。

正常完成返回退出码 0；主动接管、取消项目或明确停止并完成保存时，报告状态为 `stopped`，退出码为 2；技术未达标或运行错误返回 1。停止测试可以直接在游戏中按 F9。监控工具也可向本轮 evidence 写入 `reviewer-stop.json`，包含本轮 `runId`、`reviewerRequestedStop: true` 和非空 `reason`，由同一收尾流程保存作品。

## 本地 Codex 接手

本分支为 `codex/creative-farm-preset`，基于 PR16 的 `codex/single-session-continuation`。拉取本分支后，先阅读本说明与 `AGENTS.md`，在 Windows 上构建 TestDriver 和匹配的完整包，再使用本机已经登录并选定的 Agent 后端运行 `creative-farm`。只给一次已确认的设计约定，让模型自行完成；保留无限基础材料和无总运行时限。

本地接手重点是验证真实配方筛选、制作和摆放、完整项目续作、全农场截图以及最后的原生保存。遇到接口或编译问题就在本分支修复，并补充实际运行记录。以原生图、布局和存档检查结果为准，再由玩家评审设计风格。

## 首轮小院验证记录（旧版清场预设）

2026-11-06 在 Windows、Stardew Valley 1.6.15／SMAPI 4.2.1 上构建完整发行包及匹配 TestDriver，使用已登录 agy／gemini-3.8-flash 和单人标准农场副本，仅提交一次默认设计要求；监控间隔 15 分钟，没有设置总时长或预算上限。原生制作、摆放和复载观察确认 28 格铺路（木地板、鹅卵石各 14）、2 只箱子、1 处篝火及 2 座火盆，原建筑、水体和原可达入口保留；前后原生全图及装修存档已在本地交付，未加入仓库或发行包。

**本轮结果为 `stopped`，不是自主交付通过。** 模型约 408 秒内完成第一轮施工，但把有限工程建成受保护的 `main` 目标，收尾收到 `MAIN_GOAL_LOCKED` 后仍继续回复；49 个已完成模型回合不能作为跨回合持续施工成功的证明。经 TestDriver 调用正式 F9 处理入口接管后，没有自动夺回控制权，下一次监控保存退出，总计约 30 分 27 秒；桌面 F9 按键注入未被游戏识别，因此没有宣称物理快捷键验证通过，亦未执行通宵实测。

已修复配方字典编译错误、监控抢占运行目录、原生 PNG 文件仍占用时的读取，以及全图重复绘制 HUD；项目绑定现可识别工具边界收到的原始玩家消息，并将完成请求被拒绝作为真实故障保留作品。实际加载提示词和预设要求明确有限工程使用可完成的 `stage`，没有替模型修改旧项目状态或追加第二次任务；此收尾修复尚未重新进行完整模型实测。

另修复冻结时间事件回滚和补给节拍：原运行期间曾出现 06:00／10:00 波动且仅有初始补给，不能用最终快照的通过项代表全程正确。独立副本补验不调用模型，确认固定 10:00，原生菜单制作箱子后木材 999→949、空闲后恢复 999；装修存档成功复载，33 项摆放与原生布局一致，新全图不再带重复 HUD。

相关 Python 100 项、C# Mod 713 项及 Transport 58 项测试通过，完整发行包的便携运行环境、文件清单校验、ruff、生产／TestDriver 边界扫描通过；复载后逐格核验 28 格道路连通并连接箱子与篝火，部分连接路段被房屋图层遮住。模拟时钟跨越 12000 秒和项目重开后跨越 8000 秒仍继续的测试保留；它们不替代实机持续施工、物理 F9 或通宵验收，最终风格仍需看图评审。

## 原始农场工程调试记录

2026-11-06 使用相同游戏与 agy／gemini-3.8-flash，在独立调试副本核对未经清场的来源：1024 个地面物件、131 棵树、408 片草、39 个大型障碍及 5 处灌木，初始原生观察与另存后的占地均与来源逐项相符。第一组调试在约 11 分 44 秒内自行完成先规划、原生清理树桩／倒木／巨石及普通树草杂物、制作铺装与设施、保存和正常收尾；这只是能力调试，不能代替完整农庄交付。

后续调试修复了完整设计文本被旧 500 字协议拒绝、玩家模式拆除普通放置物被错误保护、木围栏选错工具，以及游戏原生截图文件尾部偶发未刷出的缺陷。修复后约 5 分 47 秒的调试工程成功拆除并重放地板、木围栏、熔炉和优质洒水器，实际制作摆放三种洒水器、箱子与篝火并完成耕地；配方按本机数据开放 40 种。失败或人工停止的调试单独保留，没有重发同一工程的设计要求。

# 无限材料自主装修实验

先验证一个完整的小闭环：约定农场样貌，让同一个 Agent 自行规划、制作和装修，最后交付实际农场总图、布局记录和装修后的隔离存档。材料与配方由测试环境准备，布局和施工由模型完成；采购、经营、跨日挑战与原创物件留到后续实验。

这是 PR16 基础上的 `creative-farm` 实验预设，单独运行，不加入默认三组伙伴实机回归。当前实现与验证状态见本文末尾。

## 先约定什么样的农场

默认设计约定保存在 `tools/companion_acceptance/cases.json` 的 `creative-farm.designBrief`：

> 把农场设计成木石搭配的田园小院，用至少 24 格铺路连接储物制作区与休息区。储物区放两只自己制作的箱子，休息区有一处篝火或火盆，院子至少有两处照明；形状、配色、材料搭配和位置由模型决定，保留后续耕作的空地。房屋、出货设施、水体和出入口保持原样，主要通路保持可通行。

这是一轮规模较小的设计施工实验。数量是最低交付门槛，模型可以扩大施工范围；区域关系和风格由人看最终图确认。模型可以自主修正方案和返工，先用可完成的 `stage` 目标记录工程总方案，再按真实进度更新，整项完成后收尾；`main` 是不可由模型关闭的长期目标，不用于本次有限交付。测试脚本只发送一次要求，之后观察，不补坐标、不催促下一步。

可以把自己的风格约定写成 UTF-8 文本，通过 `-DesignBriefPath` 指定。该参数替换本轮的外观描述，实验规则和客观判据仍保留；最低施工数量由 `criteria` 自动加入首次要求。改变交付数量时同步调整 `criteria` 与设计描述，启动时会冻结本轮实际使用的约定与判据。

## 这一版的创作环境

| 部分 | 本轮规则 |
| --- | --- |
| 存档 | 使用单人标准农场的隔离副本，先整理出干净施工空间；开始时保存原生布局与全农场图。 |
| 材料 | 白名单基础材料在角色背包中持续补足，保留制作产物所需空槽。补给写入独立账本。 |
| 配方 | 开放本轮选定的原生配方，具体清单在启动记录中由游戏数据确认。成品需要模型实际制作。 |
| 时间与体力 | 固定白天，持续补足体力，让本轮集中验证设计与施工。 |
| 游戏动作 | 沿用正式制作、放置、拆除与移动接口，保留原生物品消耗、碰撞和动作回执。 |
| 持续执行 | 沿用原会话与现有项目记录，一次普通回复或一个区域完成后仍可继续。 |
| 角色 | 使用 AI 自玩模式，模型控制玩家角色独立施工，沿用正式 F9 托管与接管入口。 |
| 范围 | 先做道路、围栏、箱子、篝火、火盆等已支持的可制作物件；新增家具、建筑改造与种植经营后续再做。 |

无限补给只存在于 TestDriver 的隔离预设中。生产 Mod 的制作、物品放置和资源规则保持原生行为。材料补给在动作空闲边界发生，避免改变执行中一次制作的成本和回执。

## 完成与评审

测试同时检查项目状态、真实游戏布局和动作记录。首次回复完成不会结束实验；记录设计方案但没有实际施工时继续等待。模型在项目的 `summary` 和 `layout` 保留设计说明与布局，完成总项目、原生动作结束且本轮执行稳定后，采集最终证据。

自动检查的内容包括：

- 本轮项目留下方案、布局和收尾状态，而非关闭一个无关目标。
- 新增铺路、箱子、休息物件和光源达到约定数量。
- 原有建筑保留，关键出入口仍可到达。
- 有正式制作和摆放动作及真实终态回执。
- 初始与最终原生全农场图、最终布局和执行记录齐全。
- 完成后保存隔离副本，再正常退出。

**风格、分区是否舒服、道路形状与整体留白由人工看图评审。** 结构与施工检查通过，只表示技术闭环跑通；审美结果在报告中单列，不由数量检查代替。

本实验没有总运行时限，可以持续通宵工作，直到项目完成、玩家 F9 接管、收到明确停止请求或出现实际运行错误。停止或出错时尝试保留当前状态、项目进度、实际画面与隔离存档，并报告未完成内容。连接、单次回执和结束保存仍有故障超时；它们不会按整个装修项目的累计时长中断正常施工。

## 在 Windows 上运行

准备当前分支对应的干净完整包、已登录的模型客户端、Stardew Valley、SMAPI、.NET SDK，以及源码开发所需的 Python 环境，具体构建步骤见[参与开发](../CONTRIBUTING.md)。发行包应包含 PR16 的持续执行改动；TestDriver 由入口脚本现场构建。

关闭正在运行的游戏，在仓库根目录运行一次：

```powershell
.\tools\run-companion-presets.ps1 `
  -ReleaseDir "C:\star\release\StardewAI.Companion.Mod" `
  -SavePath "C:\my-test-saves\Farm_123456" `
  -Cases creative-farm `
  -AcceptanceBackend mcode
```

路径替换为本机目录；`-SavePath` 是单人标准农场的只读来源。mcode 的模型可留空，沿用客户端配置；使用 `agy` 时建议通过 `-AcceptanceModel` 明确指定本次要测试的模型，并按需填写 `-AcceptanceEffort`。

`creative-farm` 单独运行，没有总时长预算，也无需传 `-TimeoutSeconds`；该参数仅用于其他有限时长的回归场景。正式施工每 15 分钟观察一次，动作完成回执仍由游戏即时记录；F9 立即释放游戏控制权，监控在下一次观察时采集最终图并保存退出。它会关闭周期窗口截图，保留开工前与结束时的原生全图、状态和动作账本。使用自己的设计描述时，追加：

```powershell
  -DesignBriefPath "C:\star\farm-brief.txt"
```

报告位于 `.test-runs/<运行名>-game/evidence/creative-farm-report.md`，并归档设计约定、项目方案变化、原生布局、制作与摆放记录、材料补给和前后全农场 PNG。全图通过现有 `InspectMapImage` 调用游戏原生地图截图生成，直接对应实际施工结果；截图完成后才进入交付收尾。

主要交付包括 `creative-farm-before.png`、`creative-farm-final.png`、`creative-farm-design.md` 和 `creative-farm-design.json`。装修后的存档目录、文件大小与哈希写入报告的 `savedFarm`，可用副本查看作品；它保留本次创作实验提供的材料与配方条件。

正常完成返回退出码 0；主动接管、取消项目或明确停止并完成保存时，报告状态为 `stopped`，退出码为 2；技术未达标或运行错误返回 1。停止测试可以直接在游戏中按 F9。监控工具也可向本轮 evidence 写入 `reviewer-stop.json`，包含本轮 `runId`、`reviewerRequestedStop: true` 和非空 `reason`，由同一收尾流程保存作品。

## 本地 Codex 接手

本分支为 `codex/creative-farm-preset`，基于 PR16 的 `codex/single-session-continuation`。拉取本分支后，先阅读本说明与 `AGENTS.md`，在 Windows 上构建 TestDriver 和匹配的完整包，再使用本机已经登录并选定的 Agent 后端运行 `creative-farm`。只给一次已确认的设计约定，让模型自行完成；保留无限基础材料和无总运行时限。

本地接手重点是验证真实配方筛选、制作和摆放、完整项目续作、全农场截图以及最后的原生保存。遇到接口或编译问题就在本分支修复，并补充实际运行记录。以原生图、布局和存档检查结果为准，再由玩家评审设计风格。

## 本次验证状态

2026-11-06 在 Windows、Stardew Valley 1.6.15／SMAPI 4.2.1 上构建完整发行包及匹配 TestDriver，使用已登录 agy／gemini-3.8-flash 和单人标准农场副本，仅提交一次默认设计要求；监控间隔 15 分钟，没有设置总时长或预算上限。原生制作、摆放和复载观察确认 28 格铺路（木地板、鹅卵石各 14）、2 只箱子、1 处篝火及 2 座火盆，原建筑、水体和原可达入口保留；前后原生全图及装修存档已在本地交付，未加入仓库或发行包。

**本轮结果为 `stopped`，不是自主交付通过。** 模型约 408 秒内完成第一轮施工，但把有限工程建成受保护的 `main` 目标，收尾收到 `MAIN_GOAL_LOCKED` 后仍继续回复；49 个已完成模型回合不能作为跨回合持续施工成功的证明。经 TestDriver 调用正式 F9 处理入口接管后，没有自动夺回控制权，下一次监控保存退出，总计约 30 分 27 秒；桌面 F9 按键注入未被游戏识别，因此没有宣称物理快捷键验证通过，亦未执行通宵实测。

已修复配方字典编译错误、监控抢占运行目录、原生 PNG 文件仍占用时的读取，以及全图重复绘制 HUD；项目绑定现可识别工具边界收到的原始玩家消息，并将完成请求被拒绝作为真实故障保留作品。实际加载提示词和预设要求明确有限工程使用可完成的 `stage`，没有替模型修改旧项目状态或追加第二次任务；此收尾修复尚未重新进行完整模型实测。

另修复冻结时间事件回滚和补给节拍：原运行期间曾出现 06:00／10:00 波动且仅有初始补给，不能用最终快照的通过项代表全程正确。独立副本补验不调用模型，确认固定 10:00，原生菜单制作箱子后木材 999→949、空闲后恢复 999；装修存档成功复载，33 项摆放与原生布局一致，新全图不再带重复 HUD。

相关 Python 100 项、C# Mod 713 项及 Transport 58 项测试通过，完整发行包的便携运行环境、文件清单校验、ruff、生产／TestDriver 边界扫描通过；复载后逐格核验 28 格道路连通并连接箱子与篝火，部分连接路段被房屋图层遮住。模拟时钟跨越 12000 秒和项目重开后跨越 8000 秒仍继续的测试保留；它们不替代实机持续施工、物理 F9 或通宵验收，最终风格仍需看图评审。

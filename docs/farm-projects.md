# 自主生活、农场改造与持续生产

伙伴通过已有的 Codex 会话理解目标、选择工作和调整方案。游戏提供真实状态与动作结果，并保存当前存档的项目进度。人格和记忆帮助伙伴作选择；施工方案记录想做的事，任务日志记录实际做成的事。

## 表达你想做的事

可以从伙伴对话商量，也可以在已接入游戏的 Codex 项目中提出目标：

> 想把农场整理成自然田园风，保留现在的菜地，先看看整体布局。

> 这片区域的设计和施工交给你，已有的材料可以用。

> 今天先停一下，东边那条路我想换个方向。

金币、材料、工具、地形与现有建筑由伙伴从游戏读取。你可以给风格描述或参考图片，不需要逐格安排。伙伴根据工具实际支持的能力提出方案；没有形成执行安排时只观察和商量。

装修包含整座农场的道路、生产区、建筑周围空间、绿化与休闲区域。设计可以先覆盖全场，再按实际能力和材料分区实施。

## 项目如何继续

目标保留当前阶段、简短设计说明、布局与待解决事项。暂停或重新进入后，伙伴结合任务结果和新状态继续；设计记录本身不代表已经施工。

在游戏内认可持续装修或生产安排后，伙伴接手这一项目，按阶段选择下一项工作。原本处于暂停状态时仍保持暂停，可随时在任务面板继续。普通结果保存在任务记录里；查看进度用 F8 或伙伴对话中的“看看任务进度”。外部 Codex 与游戏内入口共用任务记录，各自保留会话；选择一个入口派工，避免同时争用游戏连接。

批量施工可能只完成一部分。后续应根据实际结果补做剩余位置，不能重新扣除已完成部分的材料。遇到没有材料、目标被占用或工具不支持的情况，伙伴调整安排或说明原因。

需要商量时，伙伴会发出明确消息，例如更换整体风格或调整保留区域；日常完成不会逐条弹出。暂停与取消始终由任务面板控制。

## 持续经营

可以交代一个完整目标，例如“把这批种子种好，以后照料这片菜地”，或“建好鸡舍养十只鸡，把产物加工后放进这个箱子”。伙伴读取现有土地、住房、材料和金币，决定分批安排与补给方式；不需要你逐格指挥。

也可以一起交代“养十只鸡，同时种好这批种子”。伙伴按当天营业窗口、施工和加工等待安排顺序，在已有授权范围内自行选址；预算和需要保留的资产只需用自然语言说明。

大面积种植分批翻地、播种和浇水。水不足时补水，体力不足时结合实际食物与游戏时间安排恢复，接着处理剩余地块。跨天重新检查作物，持续照料目标不会因为今天浇完水就结束。

资源足够时，同一小批菜地可以连续播种并浇水，减少来回安排。伙伴按自己所在地点工作，玩家回屋不会让农场工作自动停下。

养殖包含住房建造与升级、购买动物、喂食和抚摸，以及拾取地面鸡蛋、机器投料、收取成品并放进指定箱子。机器未成熟时可以先做其他工作或等待，成熟后再继续；日常结果留在任务记录里。

建造要到真实柜台下单，材料和金币正常扣除，施工、动物成长和加工都需要游戏时间。持续经营需要明确交给伙伴；记忆里的喜好本身不会开启工作。重要改动再商量，随时可以暂停。

除非你指定了位置，伙伴会把最初选址当作可调整方案。发现占地时可以比较附近空地与清理障碍的成本，并在出发前查看当日节日、门的营业时间和店主状态；实际下单仍以到柜台时的游戏状态为准。

## 施工范围

- 放置伙伴背包里已有的道路地板、围栏、门、受支持家具与生产物件，以及游戏允许放置的树苗。
- 按已解锁的制作配方，使用伙伴自己的材料制作物品。
- 回收匹配的地板、围栏和可回收物件；装有物品的机器、箱子等不能作为普通装饰直接拆除。
- 单人游戏中到罗宾处新建和升级普通农场建筑，到玛妮处购买已解锁且有住房容量的动物。
- 单人游戏中移动已有建筑；目标占地需要空出，正在施工的建筑不能搬迁。普通空家具的回收也限单人游戏。

特殊家具仍需逐类扩展支持。树木生长仍需要游戏时间。先准备好材料与所需解锁条件，可以体验布局和施工；从资源不足开始的长期改造，还取决于当前可用的采集、采购和制作能力。

## 给扩展开发者

复用现有工作系统，不另建一套调度器：

- **观察**：按需读取空间信息。完整地图和布局不加入每轮默认上下文。
- **进度**：工作概览默认返回阶段、步骤状态和实际变化数量；完整布局、施工坐标和执行明细通过 `work_plan_overview(detail=True)` 按需读取。部分完成或结果未知时，先核对明细再调整剩余工作。
- **视觉**：地图图片由游戏按需生成，通过 MCP 直接交给模型。当前只能拍摄玩家所在地图；伙伴在其他地图施工时先使用结构化空间信息。
- **项目**：目标的 `project` 保存 `phase`、`summary`、`layout`、`openQuestions`，供模型参考；与执行约束分开。
- **执行**：通过现有短作业提交与执行器使用稳定命令标识，终态来自游戏。
- **恢复**：持久结果作为继续工作的依据；同一结果不因服务重启反复触发新决策。

新增动作应返回真实完成部分、未完成原因与物品变化。模型负责决定布局和策略，Mod 负责原生交互。地图修改、材料获取、建筑服务等能力各自按游戏机制实现，不能用修改存档替代施工。

能力范围与安装入口见[玩家指南](companion-guide.md)和[项目首页](../README.md)。

# 清理与兼容边界

本轮以 `cd05c4f` 为基线；小范围去重、旧组合接口退役、导航复用和职责拆分分别提交，保留独立回滚点。减少维护分叉，不以总行数作为验收目标。

## 已实施的边界

- Store 共用文件锁原语，各自保留读写事务；两个协议构造入口共用实现。聊天与工作共用 provider 等待、取消与收尾流程。
- `plant_crop_workflow` 的旧多阶段实现退役。MCP 名称与 scheduler 方法签名保留，但一律返回 `COMPOSITE_STEP_UNSUPPORTED`，不连接游戏、不创建任务、不执行动作。直接调用 scheduler 的第三方也需迁移，这是明确的兼容行为变化。
- 替代方式是根据实际观察逐次调用取种、翻地、播种与浇水，取得原生结果后再决定下一步；当前游戏 `submit_work` 不创建旧队列。旧 MCP 拒绝指引与合法原子操作测试保留。
- 锄地、播种只共用逐段步行与遇玩家重规划；各自保留动画、种子/体力结算和失败分类。
- MCP 参数契约和原生工具注册分别放入 `mcp_contract.py`、`mcp_native_tools.py`；工具仍注册到原 server，复用同一个 scheduler 和状态回调。聊天桥日志与只读 agy 用量解析独立成文件，原导入入口保留；会话恢复、回合协调和执行权保持在原入口。
- 运行提示词继续使用原路径；历史设计与当前说明分开。历史验证只证明当时的版本与范围。

## 旧执行体系使用者清单与后续设计

| 部分 | 实际消费者 | 本轮处置及后续门槛 |
| --- | --- | --- |
| `light` / `life` | 正式游戏、现有手动接入配置；八个具名工具，立即执行 | 保留；`life` 仍是 `light` 别名 |
| `full` | 通用 MCP 默认入口及兼容测试；仓外使用情况未知 | 保留默认值。若退役，应先发弃用说明和迁移版本，后续明确报错，不静默映射到 `light` |
| `internal` | `InternalMcpPlanClient`、旧 worker 的派发、取消与对账 | 先与 worker 同步迁移和验证；不得只删除工具或更换 surface |
| `PlanWorker` / 内部客户端 | `ChatBridge` 可选构造路径、旧验收工具；正式 CLI 已关闭 | 本轮保留。构造函数默认开启仍是兼容边界，不能仅因 CLI 关闭就认定无消费者 |
| `PlanExecutor` | 旧 worker 与 MCP `run_next_step` | 随上述消费者退役；先核实实例调用，不整文件搬迁或删除 |

| scheduler `reconcile_command`、超时查询和购买恢复 | 当前原生动作链路 | 保留，与旧队列退役无关 |
| `WorkStore` | 当前 decision、暂停、目标、请求与 outbox，以及旧 task/step | 保留当前状态服务。旧字段删除前先验证升级归档，不整体删除 Store |
| 旧测试与本地脚本 | 兼容契约、故障回归及本地验收 | 只删除被退役行为的专属用例；有独立原子动作覆盖的用例保留。本地脚本不作为可复现发行依赖 |

升级保留存档、会话绑定、记忆、目标和按现行规则保存的历史证据。旧任务归档并清空 task/decision；不静默续跑，不把旧回执当成当前世界状态。

## 验证要求

文件锁验证跨进程互斥、异常释放和不丢更新；协议使用现有 Python/C# 契约样本。等待流程覆盖成功、异常、取消和 executor 结束前不释放本轮执行权。

导航修改保留动作各自的动画、材料/体力结算、跳过原因和参数校验。职责拆分保留同一个 scheduler/store、协调入口和执行所有者。

运行链路改动验证完整发行包、[三组伙伴实机回归](repeatable-companion-acceptance.md)，另核对原伙伴来源、同会话重连/读档、增量送达、暂停/取消/F9、跨日和执行中退出。C# 测试必须实际运行；环境跳过不计为通过。最终结果以本轮交付记录为准，本页不是验收通过声明。

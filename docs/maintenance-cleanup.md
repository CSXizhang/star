# 清理与兼容边界

本轮以 `cd05c4f` 为基线；小范围去重、旧组合接口退役、导航复用和职责拆分分别提交，保留独立回滚点。减少维护分叉，不以总行数作为验收目标。

## 已实施的边界

- Store 共用文件锁原语，各自保留读写事务；两个协议构造入口共用实现。聊天与工作共用 provider 等待、取消与收尾流程。
- `plant_crop_workflow` 的旧多阶段实现退役。MCP 名称与 scheduler 方法签名保留，但一律返回 `COMPOSITE_STEP_UNSUPPORTED`，不连接游戏、不创建任务、不执行动作。直接调用 scheduler 的第三方也需迁移，这是明确的兼容行为变化。
- 替代方式是根据实际观察逐次调用取种、翻地、播种与浇水，取得原生结果后再决定下一步；当前游戏 `submit_work` 不创建旧队列。旧 MCP 拒绝指引与合法原子操作测试保留。
- 锄地、播种只共用逐段步行与遇玩家重规划；各自保留动画、种子/体力结算和失败分类。
- MCP 参数契约和原生工具注册分别放入 `mcp_contract.py`、`mcp_native_tools.py`；工具仍注册到原 server，复用同一个 scheduler 和状态回调。聊天桥日志与只读 agy 用量解析独立成文件，原导入入口保留；会话恢复、回合协调和执行权保持在原入口。
- 运行提示词继续使用原路径；历史设计与当前说明分开。历史验证只证明当时的版本与范围。

升级保留存档、会话绑定、记忆、目标和按现行规则保存的历史证据。旧任务归档并清空 task/decision；不静默续跑，不把旧回执当成当前世界状态。

## 验证要求

文件锁验证跨进程互斥、异常释放和不丢更新；协议使用现有 Python/C# 契约样本。等待流程覆盖成功、异常、取消和 executor 结束前不释放本轮执行权。

导航修改保留动作各自的动画、材料/体力结算、跳过原因和参数校验。职责拆分保留同一个 scheduler/store、协调入口和执行所有者。

运行链路改动验证完整发行包、[三组伙伴实机回归](repeatable-companion-acceptance.md)，另核对原伙伴来源、同会话重连/读档、增量送达、暂停/取消/F9、跨日和执行中退出。C# 测试必须实际运行；环境跳过不计为通过。最终结果以本轮交付记录为准，本页不是验收通过声明。

## 长流程实机验收（2026-10-31）

结论：经营结果通过，29 项原生状态检查通过；过程有 4 次参数拒绝、3 次原生移动受阻和一次验收脚本故障，不能称为无中断、零错误通过。同一 0.3.22 验证包、MiniMax Code 0.6.2、同一隔离存档与伙伴会话，从春 1 日运行至春 6 日，端到端 12 分 4 秒（含脚本异常恢复），5 个工作回合合计约 7 分 27 秒。

| 环节 | 实际结果 |
| --- | --- |
| 低体力起步与追加要求 | 10 点体力真实上床恢复至 80；动作中将首批收获改为保留 2 个、出货 3 个，工具边界确认送达 |
| 首日经营 | 收获 5 个防风草、拾取 3 木材；购买 5 包种子花费恰好 100 金币；原田补种 5 株、补水并浇完 |
| 连续照料 | 第二、四日完成浇水；第三日下雨，观察后不额外浇水；第五日 5 株自然成熟并全部收获出货 |

| 执行与隔离 | 51 次工作回合工具调用，其中 26 次动作调用均有终态或明确拒绝证据；步行动画变化、移动碰撞检查通过；日常存档 26 文件、安装入口 36 文件、源存档 4 文件哈希不变，测试进程已退出 |

发现与建议：

- 优先排查重复受阻：首次出货、随后导航和第五日出货前导航，共 3 次在 `Farm (68,17) → (68,16)` 收到 `MOVEMENT_BLOCKED`。模型自行绕路成功，未擅自清障、未重复出货；但后续仍选中过同一阻塞边。具体原生碰撞根因未定位，不能仅依据模型把它称为“信箱”就下结论。
- 模型有 4 次参数错误：入箱同时指定两种物品格式、种植使用错误字段两次、记事缺少触发条件；均由模型自行修正，没有替它执行或重发任务。其次改善种植参数错误提示，使其指出具体错误字段和合法格式，减少原样重试；本轮未修改生产接口或提示词。
- 第五日明知 5 株防风草已成熟且不再补种，仍先浇水再收获，原生回执记录额外消耗 5 单位水、10 点体力。需让“优先照料”结合成熟与补种计划判断，避免无效动作。
- 第三日口头预估成熟日期偏早一天；第四日仍依据未成熟观察继续照料，第五日才收获，未造成产出损失。后续宜核对播种日、所需生长天数及实际成熟状态，避免把日期估计当结论。
- 首次跨日已经结算，但菜单在采样后关闭，验收脚本误报 `Invalid menu key.` 并保存退出。保留首次失败，从原第二天存档恢复，未重布置、未补发首日任务；修正为仅容忍已消失菜单的输入竞态，最后一次真实出货跨日复验通过，相关 Python 检查 6 项通过。生产代码未改。

证据为本地 `.test-runs/long-cycle-1031/long-cycle/report.json`、`audit.json`、各阶段原生样本与公开工具 trace；首次失败在 `attempt1-report.json`，隔离及退出证明为 `final-integrity.json`、`final-processes.json`。通用启动器仍因生命周期提前保存退出而记录固定场景门禁失败，独立长流程结果不覆盖该记录。跨日由验收端操作玩家原生睡眠，每晨用自然语言要求续作；本次不证明无人值守自主跨日，也不替代此前未通过的两项 Release C# 检查。

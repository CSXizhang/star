# 0.3.5 — 伙伴交互与会话恢复修复

## 使用变化

- 认识伙伴后，入口统一为“对话 / 工作 / 设置”三页。对话保留原生头像和输入框，滚轮或 PageUp / PageDown 浏览历史；工作详情和用量按需展开。
- 待决定事项支持逐条删除、清除全部和 8 秒内撤销。删除状态保存在当前存档对应的数据中；删除和撤销不调用模型，也不代表同意执行。
- 回车始终发送普通聊天。只有从工作页选中事项并点击“确认选择”，才正式答复该事项，避免新指令被旧问题的确认状态拦住。

## 运行修复

- 保存成功初始化的会话标记，服务重启后继续使用；同一模型会话只接收一次读档变化，完整恢复背景留给新会话。失败的发送会保留重试机会。
- 工作会话继续时不重复发送整份固定规则和读档背景，保留本轮实时事实及目标。
- MiniMax Code 提示明确列出实际注册的完整工具名，避免 trace 中的 `Tool manage_milestones not found`；要求按注册 schema 填参，成功写入工作前不得声称已派工。
- MiniMax 一次执行汇总的多次请求输入量不再冒充最新请求的上下文长度；用量统计继续保留，无法测得单次长度时采用既有轮次上限。

## 验证范围

自动回归覆盖会话恢复、读档变化去重、删除持久化、撤销及模型隔离。通过隔离游戏存档检查原生页面切换、聊天、设置与事项操作。MiniMax 适配通过模拟 CLI 验证发送内容，本次未调用付费模型。

旧会话内已经存在的重复文本无法从提供方会话中回删，本版阻止后续重复注入；已有会话仍按正常轮换规则更新。升级前没有游戏内伙伴检查点的存档，不能精确还原当时的伙伴体力、背包和历史工作进度。

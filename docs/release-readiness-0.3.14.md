## 本次收尾修复

1. 默认时间预算来自 Python 协议/客户端以及 C# 动作请求，并非玩家要求。统一将 0 定义为不限游戏时长；仅显式正数启用预算，不通过提高常数掩盖问题。原先按整项作业累计的 tick 超时改为无进展检测，正常移动、处理目标及真实资源变化会刷新检测。时间仍按实测记录。
2. 本机 1.6.15 游戏程序集的 `WateringCan.DoFunction` 用 `Game1.currentLocation` 判断补水格，随后才在传入的地图浇地。原补水适配器已处理这个上下文，浇水适配器遗漏。现在两者复用同步地图上下文，并在异常时同样恢复；没有改土壤状态或替换玩家对象。
3. `already-full` 直接满足一项补水服务，不尝试剩余候选，不伪造新增水量。浇水回执补齐逐格失败/跳过原因，避免下游仅收到失败数量而丢失依据。

这轮 23 格失败的直接日志原因、零体力/水消耗模式与地图上下文缺陷吻合；修复后的跨地图实际游玩仍待确认。没有将原有其他 Mod 列为已证实的根因。
